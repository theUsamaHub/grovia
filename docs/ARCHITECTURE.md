# Architecture decisions — phase 1

- Expo SDK 58 selected from the official versioned starter and npm registry on 27 October 2026. SDK compatibility is resolved by Expo CLI and recorded in the npm lockfile.
- Native Android/iOS are the product targets. Web exists for convenient shell preview.
- Keep screens thin. Future feature logic lives outside the route directory.
- SQLite will be the durable source of truth. Zustand should contain transient UI state, not the only copy of a timer or task.
- Before adding tables: define migrations, foreign keys, indexes, deletion rules and import schema. No speculative database schema is introduced in setup.
- Future timers must persist timestamps and reconstruct elapsed time after restart; JavaScript intervals are display updates only.
- Keep all seven approved font weights local and load before showing the routed UI. A font failure reaches the route error boundary rather than hanging on the splash indefinitely.
- Respect system theme and font scaling. Proposed dark tokens need design review.
- No permissions are requested at boot. Audio recording and background playback are disabled until a tested feature needs them.
- The branding board is reference material under docs, not a bundled app asset.
- Native directories are generated by Expo and ignored in Git. Changes belong in config plugins/app.json.
- Permanent application IDs, EAS project ownership, signing, launch icons and splash artwork remain release configuration decisions.
